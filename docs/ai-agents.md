# Claude Code 서브에이전트 사용법

이 레포에는 Claude Code가 기능 하나를 PRD부터 문서까지 단계별로 만들도록 서브에이전트 8개를 넣어 두었다. 이 문서는 Claude가 규칙을 기억하는 방법과 서브에이전트를 부르는 방법을 정리한다.

## 1. 메모리: Claude가 규칙을 기억하는 방법

Claude는 대화가 끝나면 내용을 잊는다. 다음 대화에서도 지켜야 할 규칙은 아래 파일 중 하나에 적어 둔다. Claude Code는 세션을 시작할 때 이 파일들을 자동으로 읽는다.

| 파일 | 범위 | 커밋 | 언제 쓰나 |
| --- | --- | --- | --- |
| `CLAUDE.md` (레포 루트) | 이 레포, 팀 전체 | O | 팀 규칙. 폴더 구조, 금지 사항, 파이프라인 순서 |
| `.claude/agents/*.md` | 이 레포, 에이전트별 | O | 특정 에이전트의 역할과 작업 원칙 |
| `CLAUDE.local.md` (레포 루트) | 이 레포, 나만 | X | 개인 취향. 답변 말투, 내 로컬 환경 |
| `~/.claude/CLAUDE.md` | 내 모든 프로젝트 | X | 프로젝트와 상관없는 내 습관 |
| 자동 메모리 (`~/.claude/projects/<프로젝트>/memory/`) | 이 레포, 나만 | X | 대화 중 "기억해"라고 한 것을 Claude가 직접 저장 |

### 기억시키는 방법

- **팀 규칙으로 남기기:** `CLAUDE.md`를 직접 고치거나 Claude에게 "CLAUDE.md 핵심 규칙에 ~ 추가해줘"라고 한다. 커밋하면 팀원도 같은 규칙으로 작업한다.
- **나만 기억시키기:** 대화 중 "앞으로 ~ 해줘, 기억해"라고 말한다. Claude가 자동 메모리에 한 줄로 저장하고, 다음 세션부터 지킨다. 내 컴퓨터에만 남는다.
- **확인·수정:** `/memory` 명령으로 지금 읽고 있는 메모리 파일을 열어 보고 고칠 수 있다. 틀린 기억은 "그거 잊어줘"라고 하거나 파일에서 지운다.

### 처음 쓸 때, 규칙을 바꾼 뒤

`CLAUDE.md`는 **세션을 시작할 때 한 번** 읽힌다. 세션 도중에 만들거나 고친 내용은 그 세션에 자동으로 반영되지 않는다 (예: 답변 말투 규칙을 추가했는데 계속 길게 답한다).

이럴 때 입력창에 아래 명령을 친다.

```
/reread
```

`CLAUDE.md`와 `.claude/agents/`를 다시 읽고 바로 다음 답변부터 그 규칙을 따른다. 명령 정의는 `.claude/commands/reread.md`에 있다.

### 서브에이전트가 실행되지 않을 때

입력창에 아래처럼 요청한다. `CLAUDE.md`의 작업 파이프라인(pm → architect → coder → …)대로 서브에이전트가 일한다.

```
에이전트를 이용해서 CLAUDE.md 파이프라인으로 작업해
```

서브에이전트가 실제로 실행되는지는 두 곳에서 확인한다.

- 대화창에 `Agent: ...` 줄이 나온다. 이 줄이 보이면 해당 서브에이전트가 실행 중이다.
- 입력창 아래, 모델 이름 옆에 `1 agents`처럼 실행 중인 서브에이전트 수가 표시된다. 에이전트가 끝나면 사라진다.

에이전트에 지정된 모델(`.claude/agents/*.md`의 `model`)이 적용되지 않으면 아래처럼 요청한다.

```
각 서브에이전트에 맞는 모델을 적용해서 작업 진행해
```

| 상황 | 할 일 |
| --- | --- |
| 레포를 처음 받아 Claude Code를 연다 | 따로 할 일 없다. 첫 세션부터 자동으로 읽는다 |
| 세션 도중 `CLAUDE.md`를 만들었거나 고쳤다 | `/reread` |
| Claude가 규칙(말투 등)을 안 지킨다 | `/reread` |
| `.claude/agents/*.md`를 고쳤다 | `/reread`, 그래도 반영이 안 되면 새 세션을 연다 |
| 제대로 읽었는지 확인하고 싶다 | `/memory`로 읽고 있는 파일 목록을 본다 |

`CLAUDE.md 내용을 메모리에 기억해줘`라고 할 필요는 없다 (`/reread`를 쓴다). 이미 매 세션 읽히는 파일이라, 메모리에 복사하면 같은 규칙이 두 곳에 생기고 나중에 `CLAUDE.md`를 고쳤을 때 옛 내용이 남는다. 이렇게 요청하면 Claude는 `CLAUDE.md`에 없는 사실만 골라 저장한다.

### 어디에 적을지 고르는 기준

- 팀원 모두가 지켜야 하면 `CLAUDE.md`
- 특정 에이전트(예: 리뷰어)만 지키면 `.claude/agents/<이름>.md`
- 나만 원하는 것이면 "기억해" 또는 `CLAUDE.local.md`
- README·`docs/`에 이미 있는 사실은 다시 적지 않는다. `CLAUDE.md`는 그 문서를 가리키기만 한다.

> `_workspace/`는 메모리가 아니다. 요청 하나를 처리하는 동안 에이전트끼리 주고받는 작업 파일이고, 새 요청이 오면 덮어쓴다.

## 2. 서브에이전트 목록

| 순서 | 에이전트 | 모델 | 하는 일 | 결과 파일 (`_workspace/`) |
| --- | --- | --- | --- | --- |
| 1 | `pm` | opus | 요청을 기능 ID·역할·수용 기준이 있는 PRD로 정리 | `01_pm_prd.md` |
| 2 | `architect` | opus | `api.ts` 타입·Query 훅, MSW, 화면, 라우트 설계 | `02_architect_design.md` |
| 2b | `designer` | sonnet | UI 비중이 큰 화면만. 기존 Tailwind 톤에 맞춘 UI 스펙 | `02b_designer_spec.md` |
| 3 | `coder` | sonnet | 설계대로 구현 | `src/*`, `03_coder_summary.md` |
| 4 | `tester` | sonnet | 테스트 작성 + `tsc`·lint·format·test 통과 확인 | `04_tester_report.md` |
| 5 | `reviewer` | opus | diff 리뷰. 승인 또는 수정 요청 | `05_reviewer_report.md` |
| 6 | `qa` | opus | PRD·설계·구현·MSW 비교 + 브라우저로 실제 확인 | `06_qa_report.md` |
| 7 | `docs` | sonnet | README 화면 목록, `docs/tech-stack.md`, JSDoc 갱신 | `07_docs_summary.md` |

에이전트 정의는 `.claude/agents/`에 있다. Claude Code 안에서 `/agents`를 입력하면 목록을 볼 수 있다.

## 3. 기능 하나를 처음부터 만들기

메인 대화창에 기능을 말하면 된다. 메인 Claude가 `CLAUDE.md`의 파이프라인대로 에이전트를 차례로 부른다.

```
S-30 임박·폐기 화면 만들어줘. 유통기한 24시간 이내 lot을 보여주고 폐기 버튼으로 폐기 처리
```

진행 순서와 사람이 할 일:

1. 메인 Claude가 요청 원문을 `_workspace/00_input/request.md`에 저장한다 (이전 요청이 있으면 덮어쓴다).
2. `pm` → `architect` (→ `designer`)가 PRD와 설계를 만든다.
3. **설계 승인:** 메인 Claude가 설계 요약을 보여 준다. 확인하고 "승인" 또는 고칠 점을 말한다. PRD의 "미확정" 질문도 이때 답한다.
4. `coder` → `tester`가 구현하고 테스트를 통과시킨다.
5. **진행 확인:** tester가 끝나면 자동으로 멈춘다. 코드를 보고 "계속"이라고 해야 리뷰로 넘어간다.
6. `reviewer` → `qa` → `docs`가 리뷰·검증·문서 정리를 한다. 리뷰나 QA에서 막히면 coder로 돌아가 고친다. 같은 단계에서 3번 넘게 막히면 멈추고 사용자에게 묻는다.
7. 커밋·push는 사용자가 요청할 때만 한다.

### 중간에 끊겼을 때

"이어서 해줘" 또는 "계속"이라고 하면 `_workspace/`를 보고 마지막으로 끝난 단계 다음부터 다시 시작한다. 새 기능을 요청하면 이전 작업 파일은 덮어쓴다.

## 4. 에이전트 하나만 쓰기

전체 파이프라인이 필요 없으면 에이전트를 이름으로 불러 한 가지 일만 시킨다. 입력창에 `@`를 치면 에이전트 목록이 나온다.

| 하고 싶은 일 | 예시 |
| --- | --- |
| 지금 바뀐 코드 리뷰 | `reviewer 에이전트로 지금 diff 리뷰해줘` |
| 테스트만 추가 | `tester 에이전트로 src/owner/inventory/api.ts 테스트 써줘` |
| 화면 디자인 점검 | `designer 에이전트로 InventoryPage가 디자인 규칙 지키는지 봐줘` |
| 문서만 맞추기 | `docs 에이전트로 routes.tsx랑 README 화면 목록 맞춰줘` |
| 브라우저 확인 | `qa 에이전트로 /owner/inventory 3초 폴링 동작 확인해줘` |

에이전트는 앞 단계 결과 파일을 입력으로 쓴다. 혼자 부를 때 결과 파일이 없으면 무엇을 보면 되는지(파일 경로, 기능 ID)를 함께 알려 준다.

## 5. 에이전트를 고칠 때

- 에이전트가 반복해서 같은 실수를 하면 `.claude/agents/<이름>.md`의 "작업 원칙"에 한 줄 추가한다. 팀 전체 규칙이면 `CLAUDE.md` "핵심 규칙"에 추가한다.
- 파일을 고친 뒤 반영이 안 되면 Claude Code 세션을 새로 연다.
- 에이전트·`CLAUDE.md`는 팀원 모두에게 적용되므로 고친 내용은 커밋 메시지에 이유를 적는다.
- 에이전트의 `_workspace/` 보고서는 짧은 메모체(caveman)로 쓴다. 코드 주석, README, `docs/`는 이 문서처럼 평이한 문장으로 쓴다.

## 6. 파이프라인을 줄이거나 바꿔도 된다

8단계 파이프라인은 기본값일 뿐이다. 작은 수정에 pm부터 docs까지 모두 돌리면 오히려 오래 걸린다. 작업이 너무 길다고 느끼면 파이프라인을 줄여도 된다.

- 단계를 합치거나 뺀다. 예: 한두 줄 수정은 `coder` → `tester`만, 문서만 고칠 때는 `docs`만 쓴다 (4장 참고).
- `.claude/agents/*.md`와 `CLAUDE.md`의 "작업 오케스트레이션"을 고쳐 각자 쓰기 편한 에이전트 구성으로 바꿔도 된다. 새 에이전트를 추가하거나 역할을 나눠도 된다.
- 내 취향으로만 쓰는 구성은 커밋하지 않는다. 팀 전체에 적용할 변경만 커밋하고, 이유를 커밋 메시지에 적는다 (5장 참고).
- 파이프라인을 바꿨으면 이 문서의 2장 목록과 3장 순서도 함께 고친다.
